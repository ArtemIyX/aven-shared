# Vue component usage reference

Import `@wellsaik/aven-shared/tokens.css` and `@wellsaik/aven-vue/style.css` once in the application entry point. Import components from the `@wellsaik/aven-vue` root entry. The API notes here describe the current implementation slice; see [component implementation status](component-implementation-status.md) before relying on an entry marked partial.

```ts
import '@wellsaik/aven-shared/tokens.css'
import '@wellsaik/aven-vue/style.css'
import {
  AvenAccordion,
  AvenButton,
  AvenButtonGroup,
  AvenCollapsible,
  AvenContainer,
  AvenFormattedValue,
  AvenGrid,
  AvenInline,
  AvenPanel,
  AvenPasswordField,
  AvenRadio,
  AvenRadioGroup,
  AvenToggleButton,
  AvenToggleGroup,
  AvenSearchField,
  AvenStack,
  AvenStat,
  AvenSplitButton,
  AvenProvider,
} from '@wellsaik/aven-vue'
```

## Provider and generated IDs

`AvenProvider` accepts `config` with `idPrefix`, `locale`, `dir`, `density`, `defaultSize`, `messages`, and `resolveIcon`. `useAvenId(explicit, part)` returns an explicit ID unchanged or allocates an instance ID using the nearest provider factory. Accordion, Collapsible, Field, and radio controls use it for linked relationships. Without a provider, IDs use a counter scoped to the current Vue app, so separate SSR and hydration app instances produce the same sequence when their component setup order matches; use a provider when an application needs an explicit prefix.

## AvenIcon

`AvenIcon` accepts `name?`, `size='md'` (`xs | sm | md | lg | number`), `strokeWidth=2`, `spin=false`, optional semantic `tone`, `unstyled=false`, and `ui.root/svg`. A named icon resolves through the nearest provider's `resolveIcon(name)` function; without a resolved icon, its default slot renders trusted Vue content such as SVG elements. Decorative icons default to `aria-hidden`; set `decorative=false` and provide the required `label` for meaningful imagery. It never interprets SVG strings. `--aven-icon-size`, `--aven-icon-color`, and `--aven-icon-stroke-width` are the component hooks; spinning stops under reduced motion. Use `AvenIconButton` for an icon action.

## AvenBadge and AvenStatusDot

`AvenBadge` is passive and has no custom events. It defaults to `tone='neutral'`, `variant='soft'`, `size='sm'`, and `max=99`. Its variants are `soft`, `solid`, `outline`, and `dot`; `count` is hidden at zero unless `showZero=true`, and values above `max` display as `max+`. If both `count` and `label` are supplied, the accessible name is the full count followed by the label, while the visible count remains capped. Leading/trailing slots decorate its default content; `ui` supports `root`, `leading`, `trailing`, and `dot`. Hooks are `--aven-badge-bg/fg/border/radius/dot-size/gap/padding`, with semantic tone token fallbacks.

`AvenStatusDot` always provides a text status: its default slot or `label` is shown, and otherwise a visually hidden `<tone> status` label is rendered. `ui` supports `root`, `dot`, and `label`; dot color, size, and spacing are adjustable through `--aven-status-dot-color/size/gap`. Color alone never carries its meaning.

## AvenLink

`AvenLink` renders a native anchor and requires `href`. It accepts `target`, `rel`, `download`, `underline='hover'` (`always | hover | none`), `variant='default'` (`subtle | standalone`), optional `tone`, `external=false`, `unstyled=false`, and `ui.root/leading/trailing`. When `target='_blank'` and `rel` is omitted, it supplies `noopener noreferrer`; an explicit `rel` is preserved verbatim. `external` adds a decorative trailing arrow unless the trailing slot is supplied. `click(MouseEvent)` forwards once without canceling or rewriting modified navigation. Slots are default, `leading`, and `trailing`. Hooks include `--aven-link-color`, `--aven-link-hover-color`, `--aven-link-pressed-color`, `--aven-link-visited-color`, `--aven-link-gap`, `--aven-link-underline-offset`, and `--aven-link-underline-thickness`. Unavailable destinations should be rendered as text instead of a disabled anchor.

## AvenButton

`AvenButton` is a native button. It defaults to `variant='solid'`, `tone='accent'`, `size='md'`, `type='button'`, `shape='rounded'`, `loadingBehavior='block'`, and `block=false`. Variants are `solid`, `soft`, `outline`, `ghost`, and `link`; tones are `neutral`, `accent`, `secondary`, `info`, `success`, `warning`, `danger`, and `critical`; sizes are `xs`, `sm`, `md`, and `lg`; shapes are `rounded`, `pill`, and `square`. `disabled` blocks all action; `loading` exposes `aria-busy` and blocks by default, while `loadingBehavior='allow'` leaves activation enabled. `type`, `form`, `formaction`, `formmethod`, `formtarget`, and other native attributes retain browser form behavior. The default slot remains the accessible name while loading.

Events `click(MouseEvent)`, `focus(FocusEvent)`, and `blur(FocusEvent)` come from the native button and are forwarded once; disabled/loading-blocked clicks are suppressed. Methods `focus()` and `blur()` act on the native button. Slots: default, `leading{disabled,loading}`, `trailing{disabled,loading}`, and `loading{loading}`. The loading slot is decorative and hidden from assistive technology; keep progress wording in the default label or an associated status message. UI parts are `root`, `label`, `leading`, `trailing`, and `spinner`, each with `class`, `style`, and `attrs`. Component CSS hooks: `--aven-button-bg`, `--aven-button-fg`, `--aven-button-border`, `--aven-button-hover-bg`, `--aven-button-pressed-bg`, `--aven-button-radius`, `--aven-button-padding-inline`, `--aven-button-min-block-size`, and `--aven-button-gap`; semantic token values are the fallbacks. `unstyled` removes visual treatment while preserving a native 44px minimum target, focus indication, form behavior, and state semantics.

## AvenIconButton

`AvenIconButton` uses the same button `variant`, `tone`, `size`, `type`, `disabled`, `loading`, and `loadingBehavior` contracts. It requires `label` for its accessible name, defaults to `variant='ghost'`, `tone='neutral'`, and `shape='square'`, and supports `shape='circle'` plus optional `tooltip`. A tooltip becomes the native `title` and supplements the required accessible label. The default slot or `icon` slot supplies decorative glyph content; the `loading` slot replaces the decorative spinner while busy. It emits the native `click`, `focus`, and `blur` events once, suppresses blocked activation, and exposes `focus()` and `blur()` methods. UI parts are `root`, `icon`, and `spinner`; `--aven-icon-button-size` customizes the glyph while the pointer target remains at least 44px. `unstyled` preserves the label, focus indicator, and target size.

## AvenPanel

Props: `as='section'` (`article | section | div | aside`), `title?`, `description?`, `padding='md'` (`none | sm | md | lg`), `variant='outline'` (`flat | outline | raised`), `headerDivider=true`, `unstyled=false`, `ui` parts `root/header/title/description/body/footer/actions/leading/trailing`. It has no custom events. Slots: `header`, `title`, `description`, default body, `footer`, `actions`, `leading`, and `trailing`. A custom `header` slot replaces the composed header.

## AvenAccordion

Generic keys are `string | number`. `items` is required and has `{ key, label, disabled? }`. `modelValue` makes the selection controlled; `defaultValue=null` initializes uncontrolled state. `multiple=false`, `collapsible=true`, `lazy=true`, and `unmountOnHide=false` are defaults. Single mode emits `Key | null`; multiple mode emits `Key[]`.

`update:modelValue(next)` and `change(next)` fire once on an accepted user toggle. Disabled items and an attempt to close the last open item when `collapsible=false` do not emit. Slots: `trigger{item,open,disabled,triggerAttrs,triggerRef}` replaces the button and must bind both `triggerAttrs` and `triggerRef` to one native button; `leading{item}`, `trailing{item}`, `indicator{open}`, and `content{item,open}`. The fallback trigger is a native button with linked `aria-expanded` and `aria-controls`. ArrowUp/ArrowDown/Home/End move focus among enabled triggers.

## AvenCollapsible

`open?` controls state; otherwise `defaultOpen=false` initializes it. `disabled=false`, `lazy=true`, `unmountOnHide=false`. User toggles emit `update:open(boolean)` and `openChange(boolean)` once. `afterOpen` or `afterClose` fires after the next Vue render tick. Slots: `trigger{open,disabled,triggerAttrs,triggerRef}` may replace the button and must bind the supplied attributes/ref; default slot supplies fallback trigger text; `leading`, `trailing`, `indicator{open}`, `content{open}`, and `panel`. No focus trap is used. Closed retained content is hidden from interaction and accessibility APIs.

## Layout primitives

`AvenStack` uses a vertical flex layout; `AvenInline` uses a wrapping row by default. Both accept `gap='space-4'` (Stack) or `gap='space-3'` (Inline), numeric pixel gaps, CSS lengths, `align`, `justify`, a restricted `as` element, `unstyled`, and `ui.root`. `AvenGrid` accepts `columns=1` or `{ base?, sm?, md?, lg? }`, with mobile-first breakpoints at 40rem, 48rem, and 64rem. It also accepts `gap='space-4'`, `as`, `unstyled`, and `ui.root`. `AvenContainer` defaults to `maxWidth='72rem'`, `gutter='space-4'`, and centered layout; it accepts a restricted semantic `as`, `unstyled`, and `ui.root`. Spacing names map to public shared CSS variables; other strings pass through as CSS values.

## AvenFormattedValue and AvenStat

`AvenFormattedValue` requires `value` and defaults to `kind='number'`; kinds are `number`, `currency`, `percent`, `date`, `datetime`, `relative`, and `duration`. `locale` falls back to provider locale. Currency defaults to USD; `digits=2` controls maximum fractional digits for number/currency/percent. Relative values are seconds from now; durations are nonnegative seconds. Invalid dates/numbers render their input text rather than `NaN`.

`AvenStat` requires `label` and `value`; `tone='neutral'`, `trend='flat'`, and `format='number'` are defaults. It accepts `trendLabel`, `description`, `currency`, and `locale`. The default slot receives `{ value }`; `trend{trend}` may replace the trend glyph and label. Trend direction is accompanied by text so meaning does not depend on color.

All listed components accept `class`, `style`, and documented `ui` part `class/style` overrides. `unstyled` removes presentation while preserving semantic structure and interaction behavior.

## AvenSearchField

`modelValue?` controls the query; otherwise `defaultValue=''` initializes internal state. `debounce=0` runs the `search({query})` event immediately after an accepted non-composition input. While composition is active, the component emits accepted model updates but delays search until composition ends. `submit({query,originalEvent})` fires on uncomposed Enter; a pending debounced search is flushed once before submit. The field accepts `label`, `description`, `error`, `required`, `disabled`, `readonly`, `invalid`, `id`, `name`, `placeholder`, `autocomplete`, `inputmode`, `clearable`, and `clearLabel='Clear search'`, plus native attributes. Slots: `label{required,invalid}`, `description`, `error{messages}`, `leading`, `trailing`, `prefix`, `suffix`, and `clear-icon`. It exposes `focus()`, `blur()`, and `select()` methods. `update:modelValue` fires for each accepted input edit; `change(string)`, `focus`, `blur`, and `clear({previousValue,originalEvent})` follow the underlying native input interaction. A native form reset restores `defaultValue` and emits an update when controlled.

## AvenPasswordField

`modelValue?` controls the value; otherwise `defaultValue=''`. `revealed?` controls visibility; otherwise `defaultRevealed=false`. `revealable=true`; accessible labels default to `Show password` and `Hide password`. Toggle emits `update:revealed(boolean)` once per user action, except when disabled or reveal is disabled. The field accepts the same label/help/error and native attributes as SearchField, with `autocomplete`, `clearable`, and `unstyled`. Slots: `label{required,invalid}`, `description`, `error{messages}`, `leading`, `trailing`, `prefix`, `suffix`, `clear-icon`, and `reveal-icon{revealed}`. The reveal action is a native `type=button` with `aria-pressed`; focus remains on that action when toggled. It exposes `focus()`, `blur()`, and `select()`. A native form reset restores both default value and visibility, emitting updates for controlled props.

## AvenField and AvenFieldset

`AvenField` accepts `id`, `label`, `description`, `error` (string or string array), `required`, `disabled`, `readonly`, `optional`, `invalid`, `orientation='vertical'` (`horizontal`), `labelWidth`, `unstyled`, and typed `ui.root/label/description/error/control`. The default slot receives `{controlId,descriptionId,errorId,invalid,controlAttrs}`; spread `controlAttrs` onto the associated native control to carry its stable ID, required/disabled/readonly state, invalid marker, and only the help/error IDs that are rendered. `label{required,invalid}`, `description`, `error{messages}`, `before`, `after`, and `actions` slots are available. The error region uses `role=alert` and becomes invalid when an error prop or error slot is present. Horizontal labels wrap into a stacked layout on narrow windows; `labelWidth` sets `--aven-field-label-width`.

`AvenFieldset` renders a native `fieldset` and `legend`, with `disabled`, `required` marker, `invalid`, `description`, `unstyled`, and `ui.root/legend/description/content`. Its description has a stable ID linked through `aria-describedby`; native fieldset disabled semantics disable descendants. Slots: default content, `legend`, and `description`.

## AvenRadio and AvenRadioGroup

`AvenRadio<T>` renders a native radio with required `value` and visible `label`. Set `name` to join a native radio group and bind `checked` to application state for controlled use; `defaultChecked` sets the initial native state. It accepts `description`, `id`, `disabled`, `required`, `invalid`, `unstyled`, and typed `ui` parts (`root`, `control`, `indicator`, `label`, `description`). `update:checked(true)` and `change({value,checked:true,originalEvent})` fire once when the native control becomes checked; native keyboard behavior and focus/blur events are preserved. The label and optional description slots replace their text.

`AvenRadioGroup<T>` accepts `items: AvenOption<T>[]`, optional `name`, `id`, `description`, and `error`, `label`, `required=false`, `orientation='vertical'`, `disabled=false`, and typed `ui` overrides. `modelValue?` controls selection; otherwise `defaultValue=null` initializes it. A user selecting a different enabled item emits `update:modelValue(value)` and `change(value)` once. It renders a fieldset and legend; shared description and error text are linked to the group. One native name is shared by all options, so browser arrow-key and Space behavior, required validation, and form submission stay native. A prevented form reset leaves state untouched; otherwise uncontrolled selection returns to `defaultValue`.

Slots: `label{required,invalid}`, `description`, `item{item,key,selected,active,disabled}`, `indicator{checked,item,key}`, and `error{message}`. The library owns the input and label; item slots should provide descriptive noninteractive content only. `active` tracks keyboard focus, while `selected` tracks the committed value.

## AvenToggleButton and AvenToggleGroup

`AvenToggleButton` is a native button with `aria-pressed`. `modelValue?` controls pressed state; otherwise `defaultValue=false` starts uncontrolled state. It defaults to `type='button'`, accepts `disabled`, optional accessible `label` (required for icon-only content), `unstyled`, and typed `ui` parts (`root`, `label`, `leading`, `trailing`, `indicator`). Activation emits `update:modelValue(boolean)` and `change(boolean)` once. Slots are default, `leading`, `trailing`, and `indicator{pressed}`. Native attributes and listeners stay on the button.

`AvenToggleGroup<T>` renders a toolbar and accepts `items: AvenOption<T>[]`, `multiple=false`, `allowEmpty=true`, `orientation='horizontal'`, `size='md'`, `tone='accent'`, optional group `label` and `name`, `disabled`, `unstyled`, and typed `ui` parts. Single mode accepts/emits `T | null`; multiple mode accepts/emits `T[]`. `modelValue?` controls the selection; otherwise `defaultValue=null`. Activating a different enabled item emits the full next selection in `update:modelValue` and `change`. Activating a selected item clears it only when `allowEmpty=true`. Arrow keys move focus among enabled buttons and Home/End move to the first/last enabled button; focus movement does not change selection. Space and Enter use native button activation. Slots: `item{item,key,selected,active,disabled}`, `leading{item}`, `trailing{item}`, and `indicator{item,selected}`. `active` is focused state and `selected` is committed selection. When `name` is supplied, selected values submit as repeated native hidden inputs for multiple selection or one value for single selection.

## AvenListbox

`AvenListbox<T>` accepts `options: AvenOption<T>[]`, `multiple=false`, `orientation='vertical'`, `selectionBehavior='toggle'`, `loop=false`, optional `name` and accessible `label`, `disabled`, `readonly`, `unstyled`, and typed `ui.root/option/group/indicator/empty`. `modelValue?` controls the selection; otherwise `defaultValue=null`. Selection uses `T | null` in single mode and `T[]` in multiple mode. Arrow keys move the active option without conflating active focus with committed selection; Home/End move to the first/last enabled option, typeahead finds labels, and Enter/Space commits. `highlight({value,index,originalEvent})` fires when keyboard, pointer, or initial focus changes the active option; reaching the final enabled row emits `endReached({lastKey})` once upon entering the final enabled row. Selection emits `update:modelValue` and `change` once. The optional `name` submits each selected value through hidden native inputs. Rows stay mounted: a future virtualization adapter must measure consumer-provided option slots and preserve a mounted active descendant before it can safely be exposed as a prop. Slots: `item{item,key,index,selected,active,disabled}`, `group{group}`, `indicator{selected}`, `empty`, `header`, `footer`, and `separator`. The root is a focusable `role=listbox`; options use `role=option`, disabled options stay out of keyboard navigation, and active IDs remain stable for the rendered collection.

## AvenSlider and AvenRangeSlider

Both slider components use native range inputs for keyboard behavior and value semantics. `AvenSlider` defaults to `modelValue` uncontrolled `defaultValue=0`, `min=0`, `max=100`, `step=1`, horizontal orientation, and non-inverted direction. `AvenRangeSlider` defaults to `[0,100]`, with `minGap=0`; `startLabel` and `endLabel` name the two thumb controls. Both accept optional marks, a `formatValue` callback, `disabled`, `readonly`, `unstyled`, and typed `ui` parts. Value updates emit `update:modelValue` for accepted native input; native `change` emits the committed value once. Pointer gestures emit `dragStart({thumb,value})` and `dragEnd({thumb,value})`, with thumb index `0` for the single slider and `0|1` for the range. The range clamps thumbs so they never cross and honors `minGap`. Uncontrolled values restore their defaults on an uncanceled native form reset; controlled values emit an update request to the default on reset. Slots are `leading`, `trailing`, `mark{value,label}`, and `value{value,index}`; range value slots appear only when supplied. The single slider exposes `focus()` and `blur()`; the range exposes `focus(index=0)` and `blur(index=0)`. `readonly` retains focus and value announcement while preventing keyboard/pointer changes. Native input attributes and listeners are forwarded to the range input(s).

## AvenCombobox and AvenMultiSelect

`AvenCombobox<T>` defaults to single selection; `AvenMultiSelect<T>` fixes multiple selection and returns `T[]`. Both accept `options: AvenOption<T>[]`, controlled or uncontrolled `modelValue`, `query`, and `activeKey`, with `defaultValue`, `defaultQuery`, and `defaultActiveKey` for uncontrolled state; they also support `filter`, `remote=false`, `loading=false`, `error`, `clearable=false`, `creatable=false`, `maxSelected`, `open`, `defaultOpen=false`, `placement='bottom'`, optional `popupWidth`, label/help/error text, `required=false`, `requiredMessage='Please select an option.'`, disabled/readonly/invalid, `name`, `unstyled`, and typed root/control/popup/option/chip/clear UI parts. A required selection uses native input custom validity, so typing an unmatched query cannot satisfy required validation. Local filtering matches labels and keywords; `remote=true` returns the supplied options without filtering and performs no network request. `update:query` lets applications request async results; `update:activeKey` reports controlled keyboard movement; `highlight({key,item})` reports a newly active option, and `loadMore({query,lastKey})` signals that keyboard focus reached the last result. Selecting emits one `select({key,item,originalEvent})` request, `update:modelValue`, and `change`; `change` represents committed selection. `create({query,originalEvent})` asks the application to validate/create and never inserts an option automatically. Removing a chip emits an update, change, and `remove({value,originalEvent})`; clearing emits an update, change, and `clear({previousValue})`. Uncontrolled selection/query restore defaults on an uncanceled native form reset; controlled state emits default-value update requests. Reset also closes the popup. Hidden inputs submit selected keys by `name`.

The text input has `role=combobox`, list autocomplete, expanded/controls/active-descendant state, and help/error relationships. Arrow keys move through enabled options; Enter commits the active option or emits a create request when configured. Escape closes and restores focus; Tab closes without trapping focus. Spaces remain ordinary query text. IME composition never commits early. `selected{items}`, `chip{item,remove,disabled}`, `option{item,key,index,selected,active,disabled}`, `group{group}`, `leading`, `trailing`, `empty{query}`, `loading`, `error{error}`, `create{query}`, `popup-header`, `popup-footer`, `label`, and `description` slots are available. Custom chips must keep a remove action as a separate button and call the supplied `remove` callback. Popup content stays in the combobox subtree so nested theme and direction overrides inherit naturally.

## AvenContextMenu and AvenMenubar

`AvenContextMenu<Key>` requires `items: AvenCommand<Key>[]`; `open?` controls state or `defaultOpen=false` initializes it. `disabled=false`, `activation='contextmenu'`, `label='Context actions'`, and `triggerLabel='More actions'` are defaults. It opens from the pointer context menu, Shift+F10, the Context Menu key, or its visible touch-friendly action button; `activation='both'` also opens on a regular click of the target region. `openAt(x,y)` is exposed and passed to the default slot for application-controlled regions. `update:open(boolean)` and `openChange({open,reason,point?})` distinguish context, keyboard, trigger, Escape, outside, and programmatic transitions. `select({key,item,originalEvent})` requests a command; the component does not execute it. Escape restores focus to the opener and outside pointer press closes the popup. Slots: default `{openAt,open}`, `trigger{triggerAttrs,open}`, `item{item,key,active,disabled}`, `header`, and `footer`.

`AvenMenubar<Key>` requires `items: AvenCommand<Key>[]` and an accessible `label`. `loop=true`, `density='comfortable'`, `disabled=false`, and `unstyled=false` are defaults. Items with `children` open a menu; leaf items emit `select({key,item,originalEvent})`. Left/Right move focus through enabled top-level menu items and reverse in RTL; Home/End move to the first/last item; ArrowDown opens a submenu. Escape and an outside pointer press close the submenu and clean up their listeners. `activeKey?` and `openKey?` support controlled focus and open-submenu state, with `defaultActiveKey` and `defaultOpenKey` for uncontrolled state. Events `update:activeKey`, `update:openKey`, and `submenuChange({key,open})` report navigation state. Slots: `trigger{item,open,active,triggerAttrs}`, `item{item,key,active,disabled}`, `submenu-trigger{item,open}`, `header`, and `footer`. Nested popup depth beyond one level is not currently implemented; use standalone Menu for deeper command trees.

## AvenDialog and AvenAlertDialog

`AvenDialog` is a native modal `<dialog>` with `open?` or `defaultOpen=false`, optional `title` and `description`, `size='md'`, `closeOnEscape=true`, `closeOnOutside=true`, `showClose=true`, `restoreFocus=true`, and optional selector-based `initialFocus`. It links its generated heading and description IDs to the dialog, restores the opener after close, and emits `update:open`, `openChange({open,reason})`, cancelable `beforeClose`, `afterOpen`, and `afterClose`. Slots: `header{close}`, `title`, `description`, default `{close}`, `footer{close}`, `actions{close}`, and `close-icon`. The native dialog top layer supplies modal focus containment and background inertness in supported browsers.

`AvenAlertDialog` shares those props and events, defaults Escape and outside dismissal off, and supplies Cancel and Confirm buttons. It emits `cancel({originalEvent?})` and `confirm({originalEvent})`; cancel requests closure, while confirmation remains open by default so the application can finish asynchronous work. Set `closeOnConfirm` to close immediately. `loading`, `confirmDisabled`, and `cancelDisabled` block duplicate actions. Its `actions{confirm,cancel,loading}` slot replaces the default buttons. Both components support `unstyled`, typed `ui` parts, native attributes, and scoped class/style customization.

## AvenCommandPalette

`AvenCommandPalette<Key>` requires `items: AvenPaletteCommand<Key>[]` (commands may include `group` and `keywords`). It defaults to closed, empty query, local filtering, `closeOnSelect=true`, and no global shortcut. `open/defaultOpen`, `query/defaultQuery`, and `activeKey/defaultActiveKey` provide controlled or uncontrolled state. Remote mode shows the supplied result set unchanged and emits `loadMore({query})` at the last enabled item. Selection emits `select({key,item,originalEvent})`; active movement emits `highlight({key,item})`. The first Escape closes the suggestions and the next closes the dialog. Slots: `input-leading`, `input-trailing`, `item{item,key,active,disabled}`, `group{group}`, nested `shortcut{item}`, `empty{query}`, `loading`, and `footer`. The palette uses the combobox keyboard and IME behavior inside the native modal dialog; the application owns ranking, history, and command execution.

## AvenDrawer and AvenSheet

`AvenDrawer` composes the native dialog with logical `side='end'`, `modal=true`, `defaultSize='24rem'`, `minSize='14rem'`, `resizable=false`, Escape/outside dismissal on, a close button, and focus restoration. `open/defaultOpen`, `title`, `description`, dismiss options, `initialFocus`, `restoreFocus`, `unstyled`, and typed UI parts follow AvenDialog. `size?` is controlled; `defaultSize` initializes uncontrolled size. A resizable drawer emits `update:size` while dragging and `resizeStart/resizeEnd({size})`; keyboard arrows resize it by 16 pixels, and `resizeDisabled` disables the handle. Modal drawers use the dialog top layer and focus containment. A nonmodal drawer uses native nonmodal dialog behavior so the rest of the application remains available. Slots include `header{close}`, `title`, `description`, default `{close}`, `footer{close}`, `actions{close}`, `close-icon`, and `resize-handle{size}`.

`AvenSheet` shares the drawer API and defaults to `side='bottom'`, with rounded top corners. Logical start/end placement follows inherited direction. Size and resizing values are CSS lengths; during a drag the component emits pixel lengths so the application can persist them if needed.

## AvenAlert and AvenBanner

`AvenAlert` and `AvenBanner` default to `tone='info'`, `variant='soft'`, `dismissible=false`, `dismissLabel='Dismiss'`, `live='off'`, and `unstyled=false`. Both accept `title`, `description`, an actions slot, icon/title/content/close UI parts, native attributes, and root class/style. The Banner adds full-width spacing and a responsive layout. Dismissal emits `dismiss({originalEvent})`; the component never removes itself or application data. Live semantics are opt-in: `off` has no live role, `polite` uses `role=status`, and `assertive` uses `role=alert`. Slots are `icon`, `title`, default content, `actions`, and `close-icon`.

## AvenSplitButton

`AvenButtonGroup` wraps related buttons in a responsive horizontal or vertical group. It accepts `orientation='horizontal'`, `attached=false`, `size='md'`, optional accessible `label`, `unstyled`, and `ui.root` overrides. With a label it renders a named `role=group`; attached mode joins the child button corners, while separated mode keeps the `space-2` gap. Child actions remain independent; the group adds no arrow-key model. It forwards root attributes and exposes no custom events.

`AvenSplitButton<Key>` composes one primary `AvenButton` with a separate `AvenDropdownMenu` trigger. It requires `items: AvenCommand<Key>[]`; `open?` controls menu state, otherwise `defaultOpen=false`. `primaryDisabled` and `menuDisabled` are independent. `attached=true`, `closeOnSelect=true`, `placement='bottom-start'`, `offset=4`, `variant='solid'`, `tone='accent'`, `size='md'`, `type='button'`, and `loading=false` are defaults. `label='Actions'` names the group and `menuLabel='More actions'` names the menu trigger. `click(MouseEvent)` fires only for primary action; menu open never runs the primary action. `select({key,item,originalEvent})` forwards the chosen command. `update:open(boolean)` fires on a menu state request, while `openChange({open,reason})` reflects the menu's `trigger`, `select`, `escape`, `outside`, or `programmatic` transition. Slots: default primary label, `leading{disabled,loading}`, `trigger{triggerAttrs,triggerRef,open}`, `trigger-icon{open}`, `item{item,key,active,disabled}`, `menu-header`, and `menu-footer`. Custom triggers must bind both `triggerAttrs` and `triggerRef` to a focusable button. UI parts are `root`, `primary`, `trigger`, and `content`; `unstyled` keeps button/menu semantics and behavior.

## AvenChip and AvenTag

`AvenChip<T>` is plain content unless `interactive` is enabled. Interactive mode owns a native button and emits one `click(MouseEvent)`; `selected` reports caller state but does not mutate it. `removable` adds a separate native button, not nested inside the action. The remove button uses `removeLabel='Remove'` plus “item” for its accessible name and emits `remove({value,originalEvent})`; the consumer updates its collection. Disabled blocks both actions. UI parts are `root`, `content`, `leading`, `trailing`, and `remove`.

`AvenTag` is noninteractive content with no click or remove event. Both support `soft`, `outline`, and `solid` variants, semantic tones, `size='sm'`, `unstyled`, native root attributes, and `leading`/`trailing` slots. Chip also provides `remove-icon`. Their CSS remains scoped and token-backed.

## AvenAvatar and AvenAvatarGroup

`AvenAvatar` defaults to `size='md'`, `shape='circle'`, and lazy image loading. Initials come from the first two words of `name`; an explicit `initials` value takes precedence. Native image load and error events are forwarded once; after an error the fallback renders. Loaded images use `alt` (then `name`); use `alt=''` when nearby content names the person. A fallback is exposed as an image with `alt`, `name`, or initials as its accessible name. Slots: `fallback{name,initials}` and `status`.

`AvenAvatarGroup<T>` preserves the consumer item type in `avatar{item,index}`, `overflow{hiddenItems,count}`, and `overflowClick({hiddenItems,originalEvent})`. `items` is required, `max` limits visible avatars, `overlap=8`, and `label='People'`. `getKey(item,index)` supplies stable keys; without it the group uses an item's `key`, `id`, or `value`, then its index. The overflow is a button only when a consumer `overflow` slot is supplied. The group is a labeled `role=group`; it owns no people menu, tooltip, or navigation behavior.

## AvenKbd and AvenSeparator

`AvenKbd` accepts `keys?:string[]` and `platform='auto'`; it formats common modifier/navigation names but never registers a shortcut. Auto uses Mac glyphs on detected Mac platforms and Windows/Linux labels otherwise. The default slot supplies alternative key text. `AvenSeparator` defaults to a decorative horizontal divider. Set `decorative=false` for `role=separator` with its orientation; its optional `label` slot can describe a horizontal break and `inset` adds a logical start margin. Neither emits custom events. Both preserve root attrs/class/style and support typed UI parts and `unstyled`.

## AvenEmptyState and AvenResultState

Both accept required `title`, optional `description`, `kind='empty'`, `loading=false`, `unstyled`, and typed root/icon/title/description/actions/footer UI parts. Kinds are `empty`, `no-results`, `error`, `offline`, and `success`. `loading` marks the section `aria-busy` while retaining its current content; it never implies that a request has succeeded or failed. An error kind supplies a native “Try again” button when no custom `actions` slot is supplied; it emits one `retry({originalEvent})` request and never performs a network request.

`AvenEmptyState` is the centered general state surface. `AvenResultState` composes it with `layout='contained'` (`inline`, `contained`, or `full-page`) and `size='large'` (`compact` or `large`) presets for common result layouts. Both expose `illustration`/`icon`, `title`, `description`, default content, `actions`, and `footer` slots. Root attributes, classes, styles, and UI overrides remain available on the semantic section.

## AvenToolbar and AvenActionBar

`AvenToolbar` requires an accessible `label`; it defaults to horizontal, comfortable density, wrapping, and ordinary tab navigation. It uses a labeled group by default. Enable `keyboardNavigation` to apply `role=toolbar`, orientation semantics, and roving focus with arrow keys plus Home/End. Horizontal arrows follow RTL direction. The component restores consumer-authored `tabindex` values when keyboard navigation is disabled or the component unmounts. It does not invent adaptive overflow; consumers may pass `overflowItems` and render those in the `overflow{items}` slot. Slots: `start`, `center`, `end`, `group{key}`, `overflow{items}`, and default. Responsive wrapping keeps every child action available.

`AvenActionBar` is a selection-specific toolbar. It is absent when `selectionCount` is zero and appears for a positive count. It defaults to a selection count label and becomes a `role=toolbar` only when `keyboardNavigation` is enabled. Set `clearable` to add a library-owned clear button; it emits one `clearSelection({originalEvent})` request and leaves selection state to the application. Slots: `selection{count}`, `actions`, `start`, `center`, `end`, `overflow{items}`, and default. Both components forward native root attributes, class/style, typed `ui` parts, and preserve operation when unstyled.

## AvenToast and AvenToaster

`AvenToast<Key>` requires a stable `id`. It defaults to neutral tone, `duration=5000`, a close button, hover/focus timer pause, and polite status semantics; critical tone uses assertive alert semantics unless `live` overrides them. Set `duration=0` for persistent feedback. Expiry emits `dismiss({id,reason:'timeout'})`; close emits `reason:'close'`; `dismiss()` exposed to a consumer slot emits `reason:'programmatic'`. The toast does not remove data or steal focus. Its optional action emits `action({id,key,originalEvent})` once, then requests dismissal with `reason:'action'`.

`AvenToaster<Key>` accepts the caller-owned `items` array, `position='bottom-end'`, `maxVisible=3`, `gap='0.75rem'`, and pause settings. Items beyond `maxVisible` are not mounted and do not start timers. The owner should remove an item in response to `dismiss`; `afterClose({id})` fires after the removal transition. The `toast{item,dismiss}` slot customizes extra content inside the accessible toast shell and timer. Individual toast slots are `icon`, `title`, default content, `action{action,dismiss}`, and `close-icon`. UI parts are root/toast, and scoped styles honor reduced motion, forced colors, print, logical placement, and narrow viewports.

## AvenTextarea

`AvenTextarea` defaults to `defaultValue=''`, three rows, vertical resize, and no character count. It accepts controlled `modelValue`, `minRows`/`maxRows`, `autosize`, `maxlength`, disabled/readonly/required/invalid, native attributes, and typed `ui` parts (`root`, `control`, `footer`, `count`, `leading`, `trailing`). It exposes `focus()`, `blur()`, and `select()`. Input emits `update:modelValue(string)` except during IME composition; the composed value is emitted once at composition end. Native `change` emits the committed string. Autosize emits `resize({height})` only when its measured height changes. An uncanceled native form reset restores uncontrolled state; controlled state receives an update request for `defaultValue`. The `footer{length,maxlength}` slot replaces the default count area; `count{length,maxlength}` is the nested count slot. Leading/trailing adornments are noninteractive layout slots; put actions in adjacent native buttons.

## AvenScrollArea

`AvenScrollArea` uses a focusable native scrolling region and defaults to `type='auto'`, `orientation='both'`, `notifyEnd=false`, and an 8px end threshold. Add `label` when the scrollable region needs a distinct accessible name. `type` supports auto, always-stable scrollbar space, or hover/focus scrollbar treatment; forced colors keep scrollbars visible. Vertical-only and horizontal-only modes prevent accidental scrolling on the other axis. Native scroll attributes and listeners stay on the scroll region; the component emits one `scroll(Event)` for each native event. With `notifyEnd`, `endReached({axis})` fires once on reaching the logical end of an enabled axis and can fire again after scrolling away and returning. It never fetches data. Slots are default and optional `corner`; root UI/class/style and `unstyled` are supported.

## AvenAppShell

`AvenAppShell` provides named header, sidebar, main, inspector, footer, and statusbar layout regions without application routing or window APIs. Sidebar and inspector accept controlled `sidebarCollapsed`/`inspectorOpen` values; otherwise `defaultSidebarCollapsed=false` and `defaultInspectorOpen=false` initialize local state. The exposed `toggleSidebar()` and `toggleInspector()` methods request the opposite value and return it. Their `update:sidebarCollapsed(boolean)` and `update:inspectorOpen(boolean)` events fire for both controlled and uncontrolled toggles. Supply `sidebar-toggle{collapsed,toggle}` and `inspector-toggle{open,toggle}` slots to place consumer-owned controls; no focusable action is inserted by default. Optional labels name the shell region and side landmarks. CSS variables `--aven-shell-sidebar-size` and `--aven-shell-inspector-size` customize widths; narrow viewports stack the side regions above/below main content. `headerSticky=true` is default. All regions expose typed `ui` parts and preserve scoped theme inheritance.

## AvenSplitPane

`AvenSplitPane` renders two panes by default; `panes` can increase the count. `orientation='horizontal'` lays panes out left to right and `vertical` stacks them. `modelValue` controls pane percentages; `defaultValue` initializes uncontrolled proportions. Values normalize to 100%, and adjacent pane resizing respects `minSizes`/`maxSizes`; default minimums are 10% or 0% when `collapsible=true`. `resizeStep=1` controls keyboard changes in percentage points. Handles use the separator role with orientation and current/min/max values. Arrow keys resize in the layout direction (reversed for RTL), while Home/End request the allowed minimum/maximum. Pointer resize emits `resizeStart({sizes})` once, controlled/uncontrolled `update:modelValue(number[])` during movement, and `resizeEnd({sizes})` once on pointer up/cancel; unmount removes global listeners without leaving a drag active. The `pane{index,sizes}` and `handle{index,sizes}` slots let consumers provide content and grip visuals. Optional root `label` names its group; `labels` names each pane. Root, pane and handle UI parts, class/style and unstyled mode are supported.

## AvenStepper

`AvenStepper<Key>` renders the ordered `items` as an ordered list, with `modelValue` controlling the current key or `defaultValue` initializing local state. The first enabled item is the initial current step when neither value is supplied. `orientation='horizontal'`, `linear=true`, and `clickable=false` are defaults. Current steps are announced with `aria-current="step"`; completed and error indicators also include visible glyphs and an error label. In clickable mode, disabled or disallowed steps are native disabled buttons. Linear navigation allows enabled previous steps and only the next step after the current step reports `status='complete'`. An allowed activation emits `requestStep({key,from,originalEvent})` followed by `update:modelValue(key)`; consumers can keep controlled state unchanged while validating asynchronously. Slots `step`, `indicator`, `label`, and `description` receive `{item,index,current,completed}`; `connector` receives `{index}`. Public item, prop, event and slot types preserve the key generic. Root and part `ui`, `class/style`, `unstyled`, narrow stacked layout, RTL logical connectors, reduced motion, forced colors, and print styles are supported.

## AvenList and AvenListItem

`AvenList<T,Key>` is a semantic list with stable keys supplied by required `itemKey(item,index)`. `getLabel` supplies fallback text; otherwise object items with a `label` use that value and other items use their key. Loading, error and empty states render before the list and can be replaced by named slots; header/footer surround the content. `selectable=false` by default. When enabled, each row is a native toggle button with `aria-pressed`; selection toggles `selectedKeys` or local `defaultSelectedKeys`, emits `update:selectedKeys`, then emits exactly one `select({key,item,originalEvent})`. Disabled items use `itemDisabled` or an item's `disabled` field. Up/Down and Home/End move focus through enabled row buttons without adding listbox roles. Scroll emits its native event; `endReached({lastKey})` fires once per arrival at the logical end and resets after scrolling away. `scrollToKey(key,options?)` returns whether the row was found and `focus()` focuses the scroll region. The `item`, `leading`, `trailing`, and `separator` slots receive `{item,key,index,selected}`; header/footer/loading/empty/error are named slots. In selectable mode the trailing slot sits outside the row button, so it can contain independent actions. `AvenListItem` is a presentational `li` with leading, default, trailing and separator slots, selected/disabled state styling, density and divider options. Neither component performs filtering, fetching or listbox selection behavior.

`AvenVirtualList<T,Key>` renders a measured window from stable `items` and `itemKey`. `estimateSize=40`, `overscan=5`, and `orientation='vertical'` are defaults. Mounted rows are measured with `ResizeObserver` and their sizes remain associated with item keys; if ResizeObserver is unavailable, the estimate is used. `rangeChange({start,end})` reports the visible zero-based inclusive range only when it changes; `scroll(Event)` forwards each native event and `endReached({lastKey})` fires once per arrival at the end, resetting after leaving it. Exposed `scrollToIndex(index,options?)` and `scrollToKey(key,options?)` update the virtual window and focus the destination row or its first focusable child; invalid targets return `false`. Focused rows stay mounted when scrolling moves them outside the visible window. Rows remain semantic list items with set size and position; Up/Down or Left/Right (by orientation, with horizontal keys reversed in RTL), Home and End navigate rows without intercepting text editing. `dir='ltr'|'rtl'` overrides inherited direction when needed. Supply `label` when the scroll region needs a name. Slots are `item{item,key,index}`, `loading`, and `empty`; root, list and item support `ui`, class/style and `unstyled`. For short collections, prefer `AvenList` to keep every row in the DOM.
