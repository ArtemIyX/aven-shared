# App research: reusable UI patterns

Reviewed 2026-11-05 through public first-party help, product and design-system documentation for **16 distinct apps**. This is a documentation-based investigation, not a signed-in interaction audit, screenshot comparison, or measurement of private internals. Observations below are limited to the linked features; proposed component names and API decisions are our synthesis. A documented feature does not establish that an app exposes a reusable component API or supports both themes.

## Evidence matrix

| 1   | [Linear — Projects](https://linear.app/docs/projects)                                                                                                           | Projects have properties, list/board/timeline views, overview/issues tabs, attached views and detail sidebar.       | Compose Tabs, PropertyRow, Select, Badge and Drawer; keep project objects in the app.                                    |

## Cross-app synthesis

These are qualitative design conclusions from the sources, not a numeric frequency study of every control in every app.

| Repeated need          | Core building blocks                            | Composition                               | Guardrail                                                                   |
| ---------------------- | ----------------------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------- |
| Trigger an action      | Button, IconButton, Link, ToggleButton          | Toolbar, split action                     | A navigation link must retain link behavior.                                |
| Edit a value           | Field, Input, Textarea, Checkbox, Radio, Switch | SettingsForm, PropertyRow                 | Label, help, errors and native form integration must survive customization. |
| Choose a value         | Native Select, Listbox, Combobox                | Entity picker, multiple chips             | Do not substitute a command menu for a value field.                         |
| Access commands        | MenuItem, MenuGroup, Separator                  | DropdownMenu, ContextMenu, CommandPalette | Keep stable command keys and predictable focus.                             |
| Navigate workspace     | Link, NavItem, Collapsible, Badge               | Sidebar, Switcher, Breadcrumb, Tabs       | App owns routes and restored selection.                                     |
| Search and narrow data | SearchField, Chip, Select, DatePicker           | FilterBar, FilterBuilder, SortControl     | Separate query state, result fetching and saved view storage.               |
| Inspect/edit details   | Panel, Field, Toolbar, Dialog                   | Drawer, inspector, property sheet         | Avoid a giant app-specific inspector component.                             |
| Change presentation    | SegmentedControl, Tabs, ToggleGroup             | ViewSwitcher                              | View state differs from URL navigation and from a data filter.              |
| Work with collections  | List, Card, Table, Checkbox, Pagination         | DataTable, Tree, Board adapter            | Selection and focus differ; rows need stable keys.                          |
| Explain state          | Badge, Alert, Spinner, Skeleton, EmptyState     | Toast, loading/empty/error results        | Meaning needs text/icons alongside color.                                   |

## What should be shared versus app-owned

Share rendering, keyboard behavior, focus, controlled state contracts, typed selection, placement, responsive layout, and theme recipes. Let apps supply route targets, commands, option data, async loading, sorting/filtering semantics, saved preferences, permissions and domain vocabulary.

Advanced systems should be optional integrations: a calendar scheduler, spreadsheet-style data grid, rich text editor, financial charting terminal, kanban drag rules, and file-upload transport. Their smaller building blocks belong in core; their domain engines do not need to ship with every button consumer.

## Technical sources used for the proposed contracts

- [Vue — fallthrough attributes](https://vuejs.org/guide/components/attrs.html): single-root inheritance and explicit routing for compound components.
- [Vue — SFC CSS features](https://vuejs.org/api/sfc-css-features.html): scoped selectors, slot styling and CSS custom properties.
- [Vue — Teleport](https://vuejs.org/guide/built-ins/teleport.html): logical component relationships versus moved DOM.
- [WAI-ARIA APG patterns](https://www.w3.org/WAI/ARIA/apg/patterns/): distinguish menu, combobox, dialog, tabs, tree and other widget models.

The detailed APIs and visual variants in [the catalog](component-catalog.md) are Aven proposals, not claims about the internal APIs of the researched apps. The Aven palette comes from repository files, not colors sampled from these products.
